# v0.8 grammar and style review checklist

Use disposable Markdown sheets and a self-hosted LanguageTool server. Repeat the core pass on macOS,
Linux amd64, and the physical 2 GB Raspberry Pi 4.

## Privacy and configuration

- Open Review and confirm no request is made before grammar review is explicitly enabled and Check
  sheet is selected.
- Choose Test connection and confirm it reads `/v2/languages` without sending manuscript text.
- Test English (US), English (UK), Brazilian Portuguese, and European Portuguese.
- Test a local LanguageTool address, the NAS address, and an unreachable address. Confirm failure
  never interrupts typing or autosave.
- Confirm public `http://` addresses are rejected. For the NAS over private-network HTTP, confirm
  Check sheet stays disabled until the unencrypted-transport warning is acknowledged.
- Turn review off and restart the application. Confirm review remains off and prior findings do not
  reappear.

## Findings and replacements

- Check a sheet containing spelling, grammar, punctuation, and style problems. Confirm each finding
  has a category or rule description, explanation, context, and available replacements.
- Apply several non-overlapping replacements from top to bottom and bottom to top. Confirm each
  changes only its exact source range and autosaves normally.
- Dismiss a finding and confirm the manuscript does not change.
- Edit the sheet after a completed check, then try to apply an old suggestion. Confirm the stale
  suggestion is disabled and the application asks for a new check.
- Change the sheet externally after a completed check. Confirm old results become stale without
  overwriting either version.

## Scale and interaction

- Check a sheet longer than 20,000 characters and confirm chunked results point to the correct source
  text, including text after accented characters and emoji.
- Check Markdown containing YAML front matter, headings, emphasis, links, inline code, and fenced
  code. Confirm markup and code do not create findings and prose replacements still target the exact
  source text.
- Type continuously while a review is running. Confirm typing, focus controls, word counts, and
  autosave remain responsive; late results for the changed draft must not appear as current.
- Switch sheets or projects while a review is running. Confirm results never attach to a different
  sheet.
- Exercise Review at the minimum supported Raspberry Pi display size with mouse and keyboard.
  Confirm the editor and review pane remain independently usable and all controls stay reachable.

## NAS service

- Build `deploy/languagetool/compose-build.yaml` and confirm the official archive checksum is
  verified during the build.
- Deploy `deploy/languagetool/compose.yaml` through Portainer and confirm the container becomes
  healthy, restarts cleanly, and exposes only port 8081 on the trusted LAN.
- Run one English and one Portuguese check, then record cold-check latency, warm-check latency, and
  peak container memory.

ARM64 development-host baseline (2026-08-09, LanguageTool 6.6, 768 MB Java heap): the container
became healthy, an English cold check completed in 2.54 seconds, the first Portuguese check completed
in 3.01 seconds, and container memory was 678 MiB after both language modules had loaded. Repeat on
the physical Pi client before release; this is not a substitute for the target-hardware run.

x86-64 Synology NAS baseline (2026-08-09, Portainer CE 2.39.5 LTS, LanguageTool 6.6, 768 MB Java
heap): the prebuilt amd64 archive imported successfully, the runtime stack became healthy with zero
health-check failures, and a clean Portainer restart returned it to healthy. The server reported 60
languages, including `en-US` and `pt-BR`. The first English and Portuguese checks completed in 11.61
and 11.68 seconds respectively; a warm English check completed in 0.33 seconds. Portainer reported
roughly 680 MiB of container memory after both language modules had loaded. The service exposed only
port 8081 on the trusted LAN, and the existing Mini Story Jar service remained healthy.
